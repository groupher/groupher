# Assets Hub v4

> 状态：规划中
>
> 前置：v3 Assets tab、删除保护、provider delete queue、stats/filter 基础能力完成。
>
> 目标：把 Assets Hub 从 Dashboard 管理工具推进到内容生产链路。v4 优先理清
> image editor / cover / wallpaper 的最终图片导出边界，再让导出的图片走 Assets Hub
> 上传链路，并在业务数据中保存稳定 asset identity。

## v4 定位

v1-v3 已经证明：

```text
Dashboard upload
  -> assets-hub upload-api
  -> R2 original object
  -> Phoenix community_assets
  -> Worker public-read original
  -> Dashboard Assets tab 管理 / 删除
```

v4 要证明的是：

```text
Image editor / Cover editor / Wallpaper editor
  -> export final image Blob/File
  -> Assets Hub upload
  -> save asset identity in product data
  -> public runtime renders pure image asset
```

v4 不把 editor 的编辑态协议暴露给前台 runtime。Dashboard 可以持有裁切、缩放、滤镜、焦点、
背景配置等编辑状态，但离开 Dashboard 后，Docs cover、正文图片和 wallpaper 都应该表现为纯图片
asset，而不是 editor state。

## 范围

包含：

- 为当前 image editor 定义“导出最终图片”的边界。
- Cover / dark cover / wallpaper 复用同一个导出到上传边界。
- 导出的 `Blob` / `File` 走现有 Assets Hub 上传链路。
- 保存 `assetPublicRef`、`variant` 和必要的展示 metadata，而不是保存 provider URL 或 signed URL。
- editor image block / cover / wallpaper 的保存和渲染链路使用 asset identity。
- `article_document_asset_refs` 继续作为文章正文和 cover 的引用投影。
- Assets list 补引用可见性：`usageCount` / refs badge / refs Drawer。
- `thumbnail` / `card` logical variants 接入 Cloudflare Images Transformations。

不包含：

- PUT 成功但 finalize 失败后的 orphan object cleanup 实现。
- `/uploads` 和 `/finalize` 迁移到 Worker。
- 私有资源权限模型。
- 跨 community 资产复用。
- AI 生成素材、模板市场或素材编辑历史管理。
- 视频、音频转码。
- 多 provider migration。

orphan object cleanup 必须在 v4 文档中保留为后续项，但 v4 首版不实现。它属于后台卫生和
reconciliation，不应该挡住内容生产链路。

## Image Editor 导出边界

v4 的第一步不是上传，而是明确 image editor 如何产出最终图片。

推荐边界：

```text
editor state
  -> exportFinalImage(options)
  -> Blob/File + metadata
  -> upload to Assets Hub
```

`exportFinalImage` 输出：

```ts
type TExportedImageAsset = {
  blob: Blob
  filename: string
  mimeType: 'image/png' | 'image/jpeg' | 'image/webp'
  width: number
  height: number
}
```

约束：

- editor 内部可以继续使用 canvas、CSS preview、crop rect、transform matrix、theme preset 等编辑态。
- `exportFinalImage` 是 save/apply boundary，不是 editor mutation boundary。普通编辑操作只更新
  editor state，不自动导出或上传。
- 保存文章 / cover / wallpaper 时触发一次导出。若导出耗时明显，可以在对应编辑器里增加显式
  Apply/Export 按钮，但该按钮语义是“固化当前编辑结果”，不是普通编辑操作。
- 保存时必须导出最终 bitmap。
- 上传链路只接收最终 bitmap，不接收 editor 私有编辑态。
- 前台公开渲染不依赖 image editor runtime。
- undo/redo 只管理 editor state，不管理已上传 asset。保存成功后会生成新的 asset identity。
- 如果后续需要“重新编辑”，可以另存 editor draft/source metadata，但这不是 v4 public runtime
  协议的一部分。

## Upload 链路

导出的图片沿用现有链路：

```text
Phoenix createCommunityAssetUploadIntent
  -> assets-hub POST /uploads
  -> browser PUT R2
  -> assets-hub POST /uploads/:uploadRef/finalize
  -> Phoenix completeCommunityAssetUpload
  -> community_assets
```

上传 intent 必须带上调用场景所在 thread：

```text
Post editor image -> thread = post
Doc editor image  -> thread = doc
Cover             -> owning article thread
Wallpaper         -> nil 或后续明确的 community-level scope
```

如果 `community_assets.thread` 只能表达 article thread，wallpaper 不应强行伪装为 post/doc。v4
需要在实现前确认 wallpaper 归属是否继续放在 `community_assets.thread = nil`，还是新增更明确的
scope 字段。首版更保守的选择是：wallpaper 是 community-level asset，thread 为空，仍出现在
Assets Hub 的 All tab。

## Asset Variant 契约

v4 需要把 variant 收敛成单源契约，避免前端 block、GraphQL/API 和 Worker 路由各自定义。

首版枚举：

```text
AssetVariant = original | thumbnail | card
```

使用位置：

```text
editor image block attrs.variant
cover / wallpaper variant
GraphQL/API input/output if exposed
Worker route /a/<asset_public_ref>/<variant>
```

约束：

- 正文图片默认 `variant = "original"`。
- cover 默认 `variant = "card"`。
- `thumbnail` / `card` 是服务端 preset 名称。
- 前端不能把 variant 扩展成自由 transform 参数。
- 如果前后端和 Worker 都需要编译期共享，优先放到 `contracts/`；如果先通过 GraphQL 暴露，则后端
  schema enum 是源头，前端 codegen 消费，Worker 需要同步测试防止分叉。

## Product Data Contract

正文图片推荐保存：

```json
{
  "type": "image",
  "attrs": {
    "assetPublicRef": "asset_xxx",
    "variant": "original",
    "alt": "Hero image",
    "caption": ""
  }
}
```

cover 推荐保存：

```json
{
  "assetPublicRef": "asset_xxx",
  "variant": "card",
  "alt": "",
  "focalPoint": {
    "x": 0.5,
    "y": 0.5
  }
}
```

wallpaper 推荐保存：

```json
{
  "assetPublicRef": "asset_xxx",
  "variant": "original",
  "backgroundColor": "#000000"
}
```

说明：

- `assetPublicRef` 是稳定 public identity。
- `variant` 是服务端 preset 名称，不是自由 transform 参数。
- 正文、cover、wallpaper 不保存 R2 key、R2 signed URL 或 provider URL。
- cover / wallpaper 可以保存少量展示 metadata，例如 focal point、background color，但不要保存完整
  editor state 作为 runtime 渲染协议。

## Refs 生命周期

文章正文和 cover 继续通过 `article_document_asset_refs` 建立引用：

```text
save article body / cover
  -> parse assetPublicRef from content
  -> resolve asset id if needed
  -> CMS.Assets.link_refs(article, attrs, community: community)
```

版本流转继续使用：

```text
draft/public/preview/publish
  -> CMS.Assets.copy_refs(source_article, target_article)
```

永久删除文章继续使用：

```text
permanent delete article
  -> CMS.Assets.cleanup_refs(thread, article_id)
```

wallpaper 是否进入 `article_document_asset_refs` 需要保持边界清楚：如果 wallpaper 是 community-level
appearance，不属于某篇 article/document，就不应该写入 article refs。它可以由 community/theme 配置
自身持有 asset identity。

## Assets List 引用可见性

v4 应补齐 v3 预留的引用产品化：

```graphql
type CommunityAsset {
  id: ID
  publicRef: String
  usageCount: Int
}
```

推荐口径：

```text
usageCount = distinct(thread, article_id)
```

原因：

- Drawer 展示的是文章列表。
- 同一篇文章多处使用同一个 asset 不应该让列表显示 `3 refs` 但 Drawer 只有一篇文章。
- 如果后续要展示 block 级影响面，可以在 Drawer item 内显示 block usage count。

生命周期口径：

- `usageCount` 是列表展示口径，`deleteCommunityAsset` 是删除权威 guard；两者不能互相替代。
- article soft delete 后 refs 仍保留，因为文章可恢复，因此首版 `usageCount` 应继续计入这些 refs，
  或 Drawer 必须明确标注 deleted/restorable 状态。
- article permanent delete 后才通过 `cleanup_refs(thread, article_id)` 清理 refs。
- draft / public / preview 的 refs 复制仍遵循现有版本流转；如果同一内容有多个物理版本，v4 实现前
  需要确认是否按 physical article row 计数，还是折叠到同一个 article identity。
- 不建议简单加 `where article.status != :deleted`，除非产品明确决定 soft-deleted article 不再阻止
  asset 删除，并同步调整 Phoenix delete guard。

列表交互：

- `usageCount == 0` 不显示 badge。
- `usageCount > 0` 显示 `1 ref` / `n refs`。
- 点击 badge 打开 refs Drawer。
- Drawer 使用 `communityAssetRefs(community, assetId, filter)` 分页读取详情。
- 删除按钮仍以 Phoenix `deleteCommunityAsset` 的权威 guard 为准。

实现建议：

```text
Read.page
  -> page active assets
  -> collect asset ids
  -> one batched query counts distinct(thread, article_id)
  -> merge usage_count into entries
```

不要为每行做 N+1 resolver。

## Logical Variants

v4 的 `thumbnail` / `card` 主要是接入 Cloudflare Images Transformations。

它不是生成并保存具体文件：

```text
GET /a/:asset_public_ref/:variant
  -> Worker parses variant
  -> Worker calls Phoenix communityAssetOriginInfo(publicRef)
  -> Worker validates lifecycle + storage
  -> original: stream R2 object
  -> thumbnail/card: apply Cloudflare Images Transformation preset
  -> Cloudflare returns transformed response
  -> edge cache may cache response
```

URL 形态保持：

```text
GET /a/<asset_public_ref>/original
GET /a/<asset_public_ref>/thumbnail
GET /a/<asset_public_ref>/card
```

约束：

- R2 继续只保存 original。
- `thumbnail` / `card` 是服务端 preset。
- 前端不能传自由 `width` / `height` / `quality` / `format` 参数。
- Worker 不能绕过 Phoenix `communityAssetOriginInfo`。
- Images Transformation 请求同样不能绕过 Phoenix lifecycle check。public variant 不需要额外签名给前端，
  因为公开可读性仍由 Worker 的 Phoenix origin lookup 控制。
- 删除 asset 后，original 和 logical variants 都必须不可读。
- 如果 Cloudflare transform 失败，应返回结构化 origin/variant 错误，不能泄露 provider 细节。

首版 preset 可先保守：

```text
thumbnail:
  width: 320
  fit: scale-down
  format: auto

card:
  width: 960
  fit: scale-down
  format: auto
```

具体尺寸可以实现前按当前 cover / list UI 再定。文档层只固定“server preset，不生成实体文件”的边界。

## Legacy Content Migration

v4 首版只保证新写入内容使用 asset identity。已有内容中可能已经保存了 inline image URL、provider URL
或旧的 public URL，这些数据不能在 v4 中被静默改写。

首版策略：

```text
new content:
  save assetPublicRef + variant

old content:
  keep rendering compatible
  do not create refs automatically during render
  do not silently register external/provider URLs as community assets

later migration:
  scan article body / cover / wallpaper configs
  resolve known Groupher asset URLs where possible
  produce audit report
  rewrite to assetPublicRef only through explicit migration
  rebuild refs after rewrite
```

约束：

- v4 不实现旧内容迁移脚本，但必须在文档和实现边界里保留兼容策略。
- lazy resolve 旧 URL 风险较高，可能把外部图片误注册为社区资产，或产生用户不可见的 refs 变化。
- 如果后续做 migration，应优先生成 audit report，再执行可回滚的显式 rewrite。

## Orphan Cleanup 后续项

PUT 成功但 finalize/register 失败时，R2 可能留下没有 `community_assets` 成功登记的 object。v4
首版不实现 cleanup，但保留后续方向：

```text
periodic reconciliation
  -> list R2 object keys under community asset prefixes
  -> build keep-set from community_assets storage_key
  -> delete R2 keys not represented by keep-set and older than safety window
```

keep-set 不能只等于 active assets。后续实现时至少要考虑：

- active assets。
- deleted assets inside restorable / grace window。
- future pending-delete rows that still need retry or diagnostics。

这个能力适合与 delete_result 持久化、Queue DLQ、provider reconciliation 一起做，不放进 v4
首版。

## 验收

Product:

- image editor 能导出最终 bitmap。
- `exportFinalImage` 只在 save/apply boundary 触发，普通编辑操作不触发上传。
- cover / dark cover / wallpaper 能复用导出到上传边界。
- 上传完成后，业务数据保存 `assetPublicRef` + `variant`，不保存 R2 key 或 signed URL。
- 公开 runtime 渲染纯图片 asset，不依赖 editor state。
- wallpaper 在 dashboard 之外表现为纯图片，不再暴露 editor 形态。
- 旧 inline image URL / provider URL 内容仍可兼容渲染，但不会被静默迁移。

Backend:

- 正文和 cover 保存后，`article_document_asset_refs` 与当前内容一致。
- draft/public/preview/publish 继续复制 refs。
- 永久删除文章会清理 refs。
- wallpaper 若作为 community-level appearance，不写入 article refs。
- `pagedCommunityAssets` 返回 batched `usageCount`，无 N+1。
- `usageCount` 明确 soft delete、draft/public/preview 的计数口径，并与 Phoenix delete guard 保持一致。

Worker:

- `original` 仍走 R2 private bucket stream。
- `thumbnail` / `card` 通过 Cloudflare Images Transformations 输出。
- variants 不生成 R2 实体文件。
- `original`、`thumbnail` 和 `card` 都先通过 `communityAssetOriginInfo` 校验 lifecycle 和 storage。
- deleted/missing asset 的 original 和 variants 都返回结构化 404。

Validation:

- image export helper focused tests。
- upload flow focused tests 或 browser smoke。
- article body / cover refs lifecycle tests。
- `usageCount` GraphQL query tests。
- Worker variants route tests。

## 实施顺序

```text
1. Image export boundary
   - define exportFinalImage contract
   - define save/apply trigger timing
   - implement current image editor export to Blob/File

2. Upload integration
   - cover / dark cover use exported File
   - wallpaper use exported File
   - save assetPublicRef + variant

3. Asset identity contract
   - define AssetVariant single-source enum
   - align editor block, cover/wallpaper, GraphQL/API and Worker route

4. Refs lifecycle
   - editor image block saves asset identity
   - body / cover link_refs reads asset identity
   - keep wallpaper out of article refs unless it becomes article-owned
   - decide usageCount lifecycle counting rules

5. Assets list refs visibility
   - usageCount batched query
   - refs badge
   - refs Drawer

6. Logical variants
   - thumbnail/card server presets
   - Cloudflare Images Transformations
   - every variant still checks Phoenix origin_info
   - deleted asset blocks all variants

7. Later, not v4首版
   - legacy content migration script and audit report
   - orphan cleanup / reconciliation
   - delete_result persistence
   - upload endpoints Worker migration assessment
```
