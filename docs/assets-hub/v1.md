> 状态：v1 基础能力已落代码，待本地浏览器联调

> 目标：在 Dashboard Overview 做一个最小 demo，验证 `Phoenix -> assets-hub -> R2

## 范围

v1 只验证社区资产上传闭环，不接 Docs editor、cover、文章正文引用、variants
和删除。

包含：

- Dashboard Overview 中的最小上传 demo。
- Phoenix 生成上传 intent 和短期 capability。
- `assets-hub` 生成 R2 presigned PUT URL。
- Dashboard 直传文件到 R2。
- `assets-hub` finalize 上传结果。
- Phoenix 写入 `community_assets`。
- Dashboard 展示刚上传的资产记录。

不包含：

- 兼容旧 `register_community_asset` mutation。
- Docs editor / cover / image block 插入。
- `article_document_asset_refs` 同步。
- 删除资源。
- 图片裁切、缩略图、WebP/AVIF variants。
- multipart upload。
- risk-center 集成。
- CDN purge、provider migration、私有资源权限模型。

### Dashboard

Dashboard 只负责产品交互和浏览器直传：

- 读取用户选择的文件。
- 请求 Phoenix 创建上传 intent。
- 请求 `assets-hub` 创建 presigned upload。
- 使用 presigned URL 把文件 PUT 到 R2。
- 请求 `assets-hub` finalize。
- 展示上传状态和完成后的 asset 记录。
- 使用 Phoenix 已有资产查询刷新最近资产列表。

Dashboard 不持有 R2 token，不拼 R2 object key，不提交可信
`size_bytes/content_hash/storage_key`。

### Phoenix `CMS.Assets`

Phoenix 继续拥有业务事实：

- 用户登录和 `community.update` 权限。
- 社区范围。
- 配额和容量事实。
- `asset_public_ref`。
- canonical URL。
- `community_assets` 写入。

v1 不兼容旧 `register_community_asset` 前端注册 URL 模式。新资产只能通过
`completeCommunityAssetUpload` 这类可信 completion 写入。

### `assets-hub`

`assets-hub` 只负责对象执行事实：

- 验证 Phoenix 签发的短期 capability。
- 生成 R2 presigned PUT URL。
- 使用 R2 `HeadObject` 校验对象存在、大小、content type。
- 优先读取/校验上传时签入 R2 的 checksum，必要时才下载小文件计算 hash。
- 图片文件读取尺寸。
- 回写 Phoenix completion。

`assets-hub` 不直接查询 Phoenix 数据库。

### R2

R2 是 v1 的真实 S3-compatible provider：

- dev bucket：`groupher-assets-dev`
- region：`auto`
- endpoint：`https://<account_id>.r2.cloudflarestorage.com`
- bucket 不公开。

当前 `community_assets` 已有：

```text

```

v1 需要补：

```text

```

原因：

- canonical URL 不应该使用 DB id。
- R2 object key 和外部 URL 需要稳定公开身份。
- 后续 provider migration 时 public ref 不变。

推荐约束：

```text
unique community_assets_public_ref_index(public_ref)
```

## Object Key 与 URL

R2 object key 由 Phoenix intent 生成，并写入 capability；Dashboard 不能自定义。

推荐 original key：

```text
communities/<community_ref>/assets/<asset_public_ref>/original
```

v1 canonical URL：

```text
https://assets.groupher.com/a/<asset_public_ref>/original
```

v1 可以先只把 canonical URL 写入 `community_assets.url`，R2 执行身份写入：

```text
storage = "r2"
storage_key = "communities/<community_ref>/assets/<asset_public_ref>/original"
```

## Capability

Capability 是 Phoenix 对 `assets-hub` 的短期授权结果。它只表达“这个上传已被
Phoenix 判定允许”，不复制领域数据库。

v1 upload capability payload：

```json
{
  "purpose": "asset.upload",
  "uploadRef": "upl_xxx",
  "communityId": "123",
  "communityRef": "groupher",
  "uploaderId": "456",
  "assetPublicRef": "ast_xxx",
  "objectKey": "communities/groupher/assets/ast_xxx/original",
  "declaredFilename": "hero.png",
  "declaredMimeType": "image/png",
  "declaredSizeBytes": 123456,
  "checksumSha256": "base64-sha256-if-provided",
  "maxSizeBytes": 10485760,
  "allowedMimeTypes": ["image/png", "image/jpeg", "image/webp"],
  "expiresAt": "2026-07-27T07:30:00Z",
  "nonce": "..."
}
```

`uploadRef` 由 Phoenix intent 生成，并写入 capability。`assets-hub` 不再生成另一个
session identity；`POST /uploads/:uploadRef/finalize` 中的 `uploadRef` 必须与
capability 中的 `uploadRef` 一致。

`POST /uploads` response 不重复返回 `uploadRef`。Dashboard 和 `assets-hub` 都应从
capability 中读取它。若后续为了调试保留该字段，必须明确它只是 capability 中
`uploadRef` 的回显，不能被理解为 `assets-hub` 生成的资源。

`declaredMimeType` 是 v1 的上传 Content-Type 来源。`assets-hub` 必须校验它在
`allowedMimeTypes` 内，并把它签入 presigned PUT。Dashboard 后续 PUT R2 时必须
带相同的 `Content-Type` header。

`checksumSha256` 可选。Dashboard 如果能在上传前计算 SHA-256，应把 base64 结果
提交给 Phoenix intent；Phoenix 将它写入 capability；`assets-hub` presign 时把
它签入 R2 `x-amz-checksum-sha256`。这样 R2 可以在写入时校验对象完整性，finalize
阶段就不必为了 hash 重读整个对象。

`checksumSha256` 使用 R2/S3 需要的 base64 SHA-256 格式传输；DB 中的
`community_assets.content_hash` 统一存：

```text
sha256:<hex>
```

这样后续索引、比较和跨 provider migration 不依赖 R2 header 的编码形态。

实现可以先用 HMAC/JWT。具体算法可以在实现时定，但必须满足：

- 短期有效。
- 限 community。
- 限 object key。
- 限 MIME。
- 限大小。
- 限 purpose。
- 限 upload ref。

```text

      | 1. create intent      |                         |                      |

      |                       | check auth/passport     |                      |
      |                       | check community/quota   |                      |
      |                       | create upload_ref       |                      |
      |                       | create public_ref/key   |                      |
      |                       | sign capability         |                      |
      | 2. capability         |                         |                      |
      |<----------------------|                         |                      |
      |                       |                         |                      |
      | 3. create upload      |                         |                      |

      |                       |                         | verify capability    |
      |                       |                         | presign PutObject    |
```

## API 草案

### Phoenix GraphQL: create upload intent

```graphql
mutation CreateCommunityAssetUploadIntent(
  $community: String!
  $file: CommunityAssetUploadFileInput!
) {
  createCommunityAssetUploadIntent(community: $community, file: $file) {
    uploadRef
    assetPublicRef
    objectKey
    capability
    expiresAt
    maxSizeBytes
    allowedMimeTypes
  }
}
```

Input：

```graphql
input CommunityAssetUploadFileInput {
  filename: String!
  mimeType: String!
  sizeBytes: BigInt!
  checksumSha256: String
  assetType: CommunityAssetType
}
```

### assets-hub: create upload

```http
POST /uploads
Content-Type: application/json

{
  "capability": "..."
}
```

`POST /uploads` 不接受单独的 `contentType` 覆盖值。`assets-hub` 只能使用 capability
中的 `declaredMimeType` 和可选 `checksumSha256` 生成 presigned PUT。

Response：

```json
{
  "ok": true,
  "result": {
    "assetPublicRef": "ast_xxx",
    "objectKey": "communities/groupher/assets/ast_xxx/original",
    "upload": {
      "method": "PUT",
      "url": "https://...",
      "headers": {
        "content-type": "image/png",
        "x-amz-checksum-sha256": "base64-sha256-if-provided"
      }
    }
  }
}
```

### assets-hub: finalize

```http
POST /uploads/:uploadRef/finalize
Content-Type: application/json

{
  "capability": "..."
}
```

`:uploadRef` 必须等于 capability 中的 `uploadRef`。finalize 不依赖 `assets-hub`
进程内 session；它应从 capability 和 R2 object state 推导最终结果。

Response：

```json
{
  "ok": true,
  "result": {
    "asset": {
      "publicRef": "ast_xxx",
      "url": "https://assets.groupher.com/a/ast_xxx/original",
      "storage": "r2",
      "storageKey": "communities/groupher/assets/ast_xxx/original",
      "contentHash": "sha256:...",
      "sizeBytes": 123456,
      "mimeType": "image/png",
      "width": 1200,
      "height": 630
    }
  }
}
```

### Phoenix internal completion

`assets-hub` 回写 Phoenix 时使用 server-trusted GraphQL mutation，不暴露给普通
Dashboard 调用。

```graphql
mutation CompleteCommunityAssetUpload($input: CommunityAssetUploadCompletionInput!) {
  completeCommunityAssetUpload(input: $input) {
    id
    publicRef
    url
    storageKey
    contentHash
  }
}
```

Phoenix completion 必须幂等。重复 callback 只能返回同一条 asset，不能创建多条
`community_assets`。

## 本地联调前置

浏览器直传 R2 时，R2 bucket 必须允许 Dashboard origin 发起 PUT。v1 当前建议在
`groupher-assets-dev` 配置 dev-only CORS：

```json
[
  {
    "AllowedOrigins": ["http://localhost:3003"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type", "x-amz-checksum-sha256"],
    "ExposeHeaders": ["etag", "x-amz-checksum-sha256"],
    "MaxAgeSeconds": 300
  }
]
```

如本地 Dashboard 端口不是 `3003`，需要把 `AllowedOrigins` 和
`NEXT_PUBLIC_ASSETS_HUB_ENDPOINT` 一起改成实际端口。

## 访问与预览

v1 的 canonical URL 是稳定身份，不保证立刻可访问：

```text
https://assets.groupher.com/a/<asset_public_ref>/original
```

原因：

- R2 dev bucket 当前保持 `Public Access: Disabled`。
- v1 不做 `assets.groupher.com` 的 CDN、Worker proxy 或 origin resolution。
- v1 目标是验证可信上传和 DB 记录，不验证公共访问链路。

Dashboard Overview demo 可以先只展示 canonical URL 文本和 metadata。需要临时预览时，
可以后续增加 dev-only presigned GET，但它不属于 v1 验收前置条件。

## Orphan Object

v1 接受一种已知不完整状态：

```text
Dashboard PUT R2 成功
Dashboard 关闭页面或网络中断
finalize 没有发生
R2 中留下没有 community_assets 记录的 object
```

v1 通过以下方式降低风险：

- capability TTL 保持短期，例如 10 到 15 分钟。
- object key 必须由 Phoenix 生成，不能由 Dashboard 自由写入任意 prefix。
- finalize 幂等，用户重试不会创建重复 asset。

v1 不实现 orphan cleanup。后续 v1b 增加：

- 上传过期对象 sweeper。
- 按 prefix 和 age 清理未完成对象。
- 失败诊断保留。
- 可选 `Abort` API。

## 错误处理

v1 必须结构化返回错误：

```json
{
  "ok": false,
  "error": {
    "code": "upload_too_large",
    "message": "File is larger than the allowed size."
  }
}
```

建议错误码：

```text
invalid_capability
expired_capability
upload_too_large
mime_not_allowed
r2_presign_failed
r2_object_missing
r2_object_mismatch
hash_failed
image_probe_failed
phoenix_completion_failed
```

日志不能记录：

- R2 secret。
- service token。
- capability 原文。
- 用户上传正文。

## 实施顺序

```text
1. DB
   - community_assets 增加 public_ref。
   - 增加唯一索引。

2. Phoenix intent
   - createCommunityAssetUploadIntent。
   - 生成 uploadRef。
   - 生成 assetPublicRef。
   - 生成 R2 objectKey。
   - 可选接收 checksumSha256。
   - 签 capability。

3. assets-hub upload
   - POST /uploads。
   - 验 capability。
   - 校验 declaredMimeType 在 allowedMimeTypes 内。
   - 使用 capability MIME 生成 presigned PUT。
   - 如果 capability 带 checksumSha256，则签入 x-amz-checksum-sha256。

4. Dashboard demo upload
   - Overview 文件选择。
   - 可选计算 SHA-256。
   - 请求 intent。
   - 请求 /uploads。
   - 使用返回 headers PUT R2。

5. assets-hub finalize
   - HeadObject。
   - 校验 size/MIME。
   - 优先读取 checksum。
   - 必要时下载小文件计算 content hash。
   - 图片尺寸探测。
   - 回写 Phoenix completion。

6. Phoenix completion
   - 校验 service token。
   - 幂等写 community_assets。
   - 返回 CommunityAsset。

7. Dashboard result
   - 展示完成结果。
   - 使用 paged_community_assets 刷新最近资产列表。
```

## 验收标准

v1 完成时应满足：

- Dashboard Overview 选择一张图片后能完成上传。
- R2 bucket 中出现对应 object。
- Phoenix `community_assets` 中出现一条可信记录。
- `community_assets.public_ref`、`url`、`storage`、`storage_key`、`content_hash`、
  `size_bytes`、`mime_type`、`width`、`height` 都由服务端链路写入。
- Dashboard 能展示 canonical URL 和基础 metadata。
- 重复 finalize 不创建重复 asset。
- 过期 capability 不能创建 upload URL。
- 超过大小或 MIME 不允许的文件被拒绝。
- `POST /uploads` 不能用请求体中的 content type 覆盖 capability MIME。
- `POST /uploads/:uploadRef/finalize` 的 `uploadRef` 必须匹配 capability。
- R2 public access 仍为 disabled 时，v1 不要求 canonical URL 可直接打开。
- PUT 成功但未 finalize 的 orphan object 属于 v1 已知债务。
- `.env` 中 R2 token 不进入 git。
