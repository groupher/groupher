## 已完成证据：CommunityModerator → CommunityAdmin

当前分支已完成 Community Moderator 身份到 Admin 的运行时链路迁移。这不是 P4a 的 active finding，也不应再作为 P4b 或其他领域批次的阻塞项。

- 历史 DDL 文件名保留：`backend/api/priv/repo/migrations/20261122120000_rename_community_moderators_to_admins.exs`。旧 migration 名称是迁移历史，不代表运行时仍消费旧模型。
- 当前模型、GraphQL 与前端消费改用 `CommunityAdmin` / `pagedCommunityAdmins` / Admin 字段；数据库列、索引及社区元数据由上述 migration 重命名。
- 对 backend `lib`、frontend `core` / `dash` 的当前源码复核未发现活跃的 `CommunityModerator`、`pagedCommunityModerators` 或旧 moderator 写 mutation 调用。历史 migration、旧文档和构建产物不计为运行时 consumer。
- 此项的完成证据是源码 / schema 切换与 migration；P2 的完整回归和发布验收仍按主计划记录，不在此处声称已经完成。

## P4a 关闭条件

P4a 是源码和消费者归属盘点，不是 P4c 全局清理的前置审批。关闭前还需核对 P0 清单中的动态 mutation macro、middleware / callback 注册、生成 schema、jobs / seeds / fixtures 和客户端缓存失效；扫描结果必须把运行时调用、历史文档、测试夹具和生成产物区分开，未知入口留作明确条目，不以 `rg` 命中数或零命中代替路径证明。

每个发现项必须有唯一 owner batch、可执行的删除 / 切换方式和该批次的定向验收；consumer 在其批次内完成后即可交付，不等待其他领域。P4c 仍按 [Passport 主计划 §7](../passport-permissions-refactor.md#7-实施批次与切换) 等待 P2B、C3、D1 / D2 和 D3 完成，再统一做无残留核查、必要 DDL / 数据迁移演练及正式切换记录。
