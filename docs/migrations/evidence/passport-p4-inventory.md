## P4a 关闭条件

P4a 是源码和消费者归属盘点，不是 P4c 全局清理或其他领域交付的前置审批。本次已核对 P0 清单中的动态 mutation macro、middleware / callback 注册、生成 schema、jobs / seeds / fixtures 和客户端缓存失效。当前 60 个活跃 schema `M.Passport` action（13 Global、47 Community）全部是可授予 Catalog action，没有 Article-scope / non-grantable action 转入 Registry fallback；`article.trash.read` 是 owner-only Catalog action，用于全局 Trash 身份授权和旧规则转换，不是本站 Trash middleware action。运行时调用、历史文档、测试夹具和生成产物已区分。Passport 自有 generic middleware Registry fallback 与 HTTP Context `cur_passport` 投影现已在本地移除，底层 PermissionRegistry 旧规则工具保留其直接 callers；以上局部清理不阻塞其他领域交付。

每个发现项必须有唯一 owner batch、可执行的删除 / 切换方式和该批次的定向验收；consumer 在其批次内完成后即可交付，不等待其他领域。P4c 仍按 [Passport 主计划 §7](../passport-permissions-refactor.md#7-实施批次与切换) 等待 P2B、C3、D1 / D2 和 D3 完成，再统一做无残留核查、必要 DDL / 数据迁移演练及正式切换记录。
