# Dashboard TanStack Start V3：Platform 共存下的 TanStack 语义

> 历史设计记录：本文形成于 Next Dashboard 与 TanStack Dash 共存阶段。当前只保留
> TanStack hosts，`PlatformProvider` 已收敛为窄化的 `RouteScopeProvider`。

> 状态：实施中。
>
> V3 不迁移或替换 V2 的双 host 架构。它定义在 `frontend/dash` 继续增强
> TanStack Router/Start 语义时，如何保持 `frontend/dashboard` 的 Next.js 实现长期共存。

## 目标

V3 的目标不是让所有代码直接 import TanStack，而是让每一层使用自己拥有的
路由知识：

```text
framework-neutral Core
  -> PlatformLink / platform.navi / TRouteTarget
  -> PlatformProvider
      -> Next Dashboard: next/link + Next Router
      -> TanStack Dash: TanStack Link + TanStack Router
```

Core 表达导航语义和跨 host 的 route target；host adapter 负责把 target 解析成
各自的 URL 和 router API。`frontend/core` 不得 import `@tanstack/react-router`。

## 当前实施状态

第一批改动已落地：

- Core 的 ArticleCell 和 Collapsed submenu 已使用 `PlatformLink`。
- Dash community route 已使用 `validateSearch + loaderDeps` 处理 `lang/mode`。
- Dash doc editor route 已使用 `validateSearch + loaderDeps` 处理 `docId`。
- Dash router factory 的必要兼容 cast 已限制在单点；navigate/preload 的动态
  转换已限制在 Dash adapter helper。
- Core、Next Dashboard、Dash type-check 和相关定向测试通过。

剩余工作主要是 link regression 覆盖、search 行为测试、完整 route option 规范化
和进一步确认是否可以开启 Dash 的 `strictNullChecks`。

## 不变的架构约束

- Dash 和 Next Dashboard 长期并行，不创建中间兼容 app。
- Core 继续通过 `PlatformProvider` 访问 Link、Image、Script 和 navigation。
- `frontend/core/platform/route.ts` 继续是 DSB route target、search allowlist、
  `preserveSearch` 和 host root segment 的共享解析边界。
- `dsbRootSegment` 是 adapter 元数据，不会被直接拼进业务 URL。
- Dash 的 TanStack route tree 和 Next 的 App Router tree 不合并。
- 不因为使用 TanStack Start 就重新引入 TanStack Query；GraphQL server state
  继续由 urql 管理，request/local state 继续由现有 store 管理。
- `routeTree.gen.ts` 是生成产物，业务代码不得依赖其中的内部节点，也不得手动编辑。

## 导航语义

普通页面导航必须是语义链接：

```tsx
<PlatformLink route={target} preserveSearch>
  Open article
</PlatformLink>
```

`PlatformLink` 从 `usePlatform().components.Link` 取得 host 实现，因此同一份
Core 组件在 Next 和 Dash 中分别渲染为 Next link 或 TanStack link。

只在以下情况使用 imperative navigation：

- mutation 成功后跳转；
- 返回前需要异步确认或阻止离开；
- history、replace、refresh、prefetch 等 router 操作；
- 没有可表达页面目的地的状态控制流程。

`onClick + navi.to()` 不得作为普通页面链接的替代。Link 上允许存在不阻止默认
导航的 analytics、菜单状态同步等副作用。

### 当前首批改造范围

- `DashboardThread/CMS/Cell/ArticleCell`：文章标题改为 `PlatformLink`。
- `DashboardThread/SideMenu/Collapsed`：普通子菜单项改为 `PlatformLink`；
  “展开菜单”按钮和其他状态控制仍然使用 button。
- `SubMenuBack` 保留 button，直到异步 `runBeforeDashboardBack()` 有等价的
  link 拦截实现。

## TanStack Dash route 约定

### 文件路由

```text
routes/
  __root.tsx
  $community/
    route.tsx       父级 loader、shell、Outlet
    index.tsx        community 根路径的精确 redirect
    overview.tsx     leaf route
    doc/editor.tsx   leaf route
```

- `$param` 是 typed path param；不要拼接动态路径后使用 `as never`。
- `route.tsx` 负责稳定的父级布局和共享数据。
- leaf route 只负责页面专属 loader 和页面组件。
- 由 route generator 生成的 route tree 不进入业务模块。

### Route lifecycle

```tsx
export const Route = createFileRoute('/$community/doc/editor')({
  validateSearch: validateDocEditorSearch,
  loaderDeps: ({ search }) => ({ docId: search.docId }),
  loader: ({ params, deps }) =>
    loadDocEditorData({
      data: { community: params.community, docId: deps.docId },
    }),
  component: DocEditorPage,
})
```

- `beforeLoad`：权限、前置条件和 redirect；redirect 使用 `throw redirect(...)`。
- `loader`：route 数据读取和 SSR/preload 数据入口。
- `loaderDeps`：显式声明 loader 依赖，尤其是 search 参数。
- `validateSearch`：将 URL query 转换为 route-local 的可信类型。
- `Route.useLoaderData()` / `Route.useSearch()`：在 route-owned component 中读取。
- `notFound()`、`errorComponent`、`pendingComponent`：使用 route 生命周期表达
  404、错误和加载状态，不在组件中手写等价的 pathname 控制流。

### Search 参数边界

Dash route 自己拥有的参数（例如 `docId`）可以使用 TanStack typed search。
跨 host 或 Core 需要保留的参数仍必须经过 `TRouteTarget`、search schema 和
`resolveDsbRoute()`；不能把 `Route.useSearch()` 泄漏到 Core。

首批 route-local search 改造：

- `$community/route.tsx`：`lang`、`mode`；
- `$community/doc/editor.tsx`：`docId`。

## 类型边界

Dash adapter 可以知道 TanStack Router，但 Core 不可以：

```text
Core TRouteTarget
  -> resolveDsbRoute(target, { rootSegment: 'dash' })
  -> Dash TanStack Link / navigate / preloadRoute
```

如果 TanStack API 需要 cast，必须集中在 `frontend/dash/src/platform` 的小型
adapter 函数中，不能把 `as any`、`as never` 扩散到 Core 或业务组件。

优先级：

1. 用 route params/search 对象表达类型；
2. 用 typed adapter helper 转换 `TRouteTarget`；
3. 只有第三方 API 类型不完整时，才在 adapter 边界局部 cast，并写明原因。
