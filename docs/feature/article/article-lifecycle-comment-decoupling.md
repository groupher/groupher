# Article Lifecycle 与 Comment 社区解耦重构合同

> 状态：D1–D5 已在本地隔离环境完成实现、迁移和全链路验收；生产环境切换仍需单独执行 report/apply 与上线复核。本文是重构实施与验收合同；当前产品规则以本文及已同步的 [Article Community](./article-community.md)、[Reference Map](./reference-map.md) 为准。

## 1. 完成后的规则

普通 Post、Blog、Changelog 的 Article 是稳定身份；一篇 Article 有一份正文选版和一份 Lifecycle。`ArticleBinding(article_id, community_id)` 只表示它在某 Community 有入口。Community 的状态、binding 和明确的展示限制共同决定该入口是否可读；它们不改变 Article 的全局发布状态。Ticket 仍只有一个有效 Community binding，Doc 仍由 DocBranch/DocLifecycle 管理；这轮不把普通 Article 的 mirror 命令开放给 Ticket 或 Doc。

Comment 以稳定 Comment ID 和父 Article ID 为身份。普通 Comment 在父 Article 当前可读的任何 binding 下是同一条内容，拥有同一正文、回复、互动、Lifecycle 和审核结果。Comment 不保存创建 Community 作为归属或授权依据。Doc Comment 仍带 Doc branch ID，依 Doc main branch 的公开规则读取；不从本文推导新的 Doc mirror 规则。评论数和参与人数按 Article 汇总一次，不按 binding 复制。

任何用户从 X 或 Y 提交对同一普通 Comment 的举报，都指向同一个 Comment 审核对象。**单次举报只创建待处理事实，不自动隐藏。**达到既有阈值时，当前阈值流程可以施加 `report_threshold_hold`，这是明确例外；这不改变单次举报本身不隐藏的规则。一旦平台审核者作出隐藏决定，X/Y 的当前可读入口同时隐藏；恢复时同时可见。不存在“X 社区隐藏、Y 社区仍显示”的 Comment 产品状态，创建地管理员也不因创建地身份获得跨 Community 的全局处置权。平台审核权限负责普通 Comment 的全局决定；作者已有的编辑/删除权限仍由 Comment/Article Gate 校验。社区路径可以作为举报发生地保存在举报事实中，但不决定审核队列、审核权限或隐藏范围。Doc Comment 继续按 Doc branch 的现有审核 owner，须在测试中证明未被普通 Comment 规则误改。

```text
Article(id) ── ArticleLifecycle(article_id, state)
    │
    ├── ArticleBinding(article_id, X) ── X 页面入口
    ├── ArticleBinding(article_id, Y) ── Y 页面入口
    └── Comment(id, article_id) ── CommentLifecycle / 全局审核决定

X/Y 页面能否读到 Comment
  = 本次请求的 ArticleBinding + 父 Article 公开状态 + Comment 公开状态
```

## 3. 数据与接口终态

| 对象                                   | 唯一权威与约束                                                                               | Community 的用途                                                                            |
| -------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `cms.articles` / `cms.article_publics` | 稳定 Article ID、单一公开选版                                                                | 无持久 home/origin 关系                                                                     |
| `cms.article_lifecycles`               | `article_id NOT NULL`、唯一；Article FK；状态转移按 Article 锁与版本执行                     | 无 `community_id`；Community 删除不会级联删除 Lifecycle                                     |
| `cms.article_bindings`                 | `(article_id, community_id)` 唯一，`inner_id` 为该 Community 的公开编号                      | 只负责入口和明确的 Community-local Tag/Pin 等事实                                           |
| `cms.comments`                         | 稳定 Comment ID、父 `article_id`；Doc Comment 另有 branch ID                                 | 无 `origin_community_id`/`community_id`；从请求父 Article path 求公开上下文                 |
| Comment Lifecycle / ReviewBlock        | 普通 Comment 按 Comment ID 作一份全局决定；数据库唯一性覆盖 `NULL` Community 的 active block | 普通 Comment 不允许 Community-local block；Doc branch scope 保留原合同                      |
| `AlertWall.UserReport`                 | 每次举报的 reporter、Comment ID、时间和 observed version                                     | 可以记录举报路径的 Community，删除该 Community 后不影响举报对象                             |
| `AlertWall.Item`                       | 普通 Comment 同一目标只有一个当前全局处理对象；已结案历史不可因来源社区删除而改写            | 普通 Comment 的现有 `community_id=NULL` 表示平台队列；其他 target 的既有 scope 不随本轮改变 |

公开 GraphQL/URL 继续以 `/<community>/<thread>/<articleInnerId>` 和 Comment 的 `commentInnerId` 定位，内部 Comment ID 不出公开响应。`referenceMap`/`mentions`/`mentionedBy` 的事实、水位、opaque ID、URL 和分页合同保持；Gate 从当前父 Article binding 与全局 Comment 状态投影。Article/Comment 状态或审核变化在原事务推进所有受影响 binding 的 GraphRevision。Comment 的提交 Community 不参与同步 token、Map 边或公开节点身份。

保留现有 `FrontDesk.article_of/1` 入参和返回合同，但它只能沿 Comment 显式携带的本次请求 Community 读取父 Article；缺少请求 Community 时必须 fail closed，不能回退到创建地或任选一个 binding。公开调用也可直接使用现有 `FrontDesk.article(article_path)`；内部 Article 调用使用 `FrontDesk.article(article_id, mode: :internal, view: :command_context)`，Comment 内部上下文通过 `FrontDesk.Comment.read(comment_id, mode: :internal, view: :article_context)` 取得。`:article_context` 是 Comment view，不是 Article view。
